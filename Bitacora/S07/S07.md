# **Sistema integrado de reserva y uso de espacios**

*¿Cómo podríamos automatizar el sistema de registro y reserva de
espacios del edificio del Hub Providencia?*

Foco: Diseñar un flujo digital completo de reserva, consulta,
confirmación de uso y generación de historial.

**Equipo:** [TI+A]{.underline}

**Fecha:** [04-10-2026]{.underline}

**Integrantes:** [Antonia Reyes, Jeremy Oyarce, Benjamín Infante,
Fernando Sandoval]{.underline}

## **1. Propuesta**

*¿Qué proponemos construir y qué problema específico resolverá?*

Proponemos construir un sistema digital que centraliza el registro y
reserva de los espacios del Hub Providencia (salas, cowork y
laboratorios), reemplazando la coordinación manual por correo. Los
usuarios reservan mediante un formulario web sincronizado a un
calendario compartido, y validan su llegada físicamente con un llavero
NFC/RFID en un dispositivo instalado en la entrada de cada espacio, que
confirma la reserva y registra el uso real en tiempo real.

Resuelve específicamente: (1) la dependencia del correo electrónico para
agendar laboratorios, (2) la falta de un historial consolidado de uso, y
(3) la ausencia de datos sobre demanda y ocupación real de los espacios.

## **2. Esquemático / Bosquejo del prototipo**

*Dibuja el dispositivo, aplicación, sensor, usuario y flujo de
información. Marca con flechas qué se conecta con qué.*

-   Usuario (celular/web) → Formulario web de reserva (espacio, fecha,
    hora)

-   Formulario → Backend: Google Calendar + Sheets (bloquea el horario,
    guarda la solicitud)

-   Llegada física del usuario → Llavero NFC/RFID → Lector RFID
    conectado al ESP32

-   ESP32 procesa: ¿la reserva es válida para esta hora y este espacio?

-   Salidas del ESP32: LCD 1602 I2C (mensaje de estado), Buzzer (beep de
    confirmación o error), Módulo RGB (verde/rojo), RTC DS3231 (hora
    exacta de entrada)

-   ESP32 (vía WiFi) → actualiza Sheets → historial de uso y panel de
    indicadores

Energía: powerbank 5V por estación. Conectividad: WiFi integrado del
ESP32 hacia el backend en la nube.

## **4. Preguntas**

**¿Quién reserva, quién administra y qué pasos del proceso actual
quieren eliminar o automatizar?**

Reservan: usuarios internos y externos que usan salas, cowork y
laboratorios. Administra: el equipo de administración del Hub. Se
elimina: el envío y respuesta de correos para agendar, y la anotación
manual de reservas. Se automatiza: la solicitud, la verificación de
disponibilidad, la confirmación y el registro de uso real.

**¿Qué estados tendrá una reserva: disponible, reservada, confirmada,
usada, cancelada, no utilizada?**

Disponible → Reservada → Confirmada (check-in con RFID) → Usada →
Cancelada / No utilizada (si no hay check-in dentro del margen de
tolerancia de 10-15 minutos).

**¿Cómo comprobarán que la sala realmente fue utilizada y no solo
reservada?**

Mediante el check-in físico con el llavero RFID al llegar al espacio. Si
no se valida dentro de los primeros 10-15 minutos de la reserva, el
sistema la marca como \"no utilizada\" y libera el espacio
automáticamente, de modo que el historial refleja uso real y no solo
reservas hechas.

**¿Cómo resolverá el sistema conflictos de horario, cancelaciones y
disponibilidad?**

El backend bloquea automáticamente cualquier horario ya reservado para
un espacio, impidiendo la doble reserva. Las cancelaciones se realizan
desde el mismo enlace de confirmación y liberan el horario de inmediato.
La disponibilidad se actualiza en tiempo real en el calendario
compartido, visible para todos antes de reservar.
